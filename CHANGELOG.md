# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/)
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

- BREAKING: One `AnvilClient` replaces `RestClient` and `GraphQLClient`, which remain as thin wrappers over it, marked obsolete. One `HttpClient` pipeline sends REST and GraphQL requests, so auth, rate limiting, retries and errors are the same for both. The `GraphQL.Client` dependency is gone, and with it a transitive `System.Text.Encodings.Web` 4.7.0 flagged as a critical vulnerability. The package targets `netstandard2.0` and `net10.0`.
  - `new AnvilClient(new AnvilClientOptions { ApiKey = ..., BaseUrl = ... })` sends every request to one host: REST to `{BaseUrl}/api/...`, GraphQL to `{BaseUrl}/graphql`. `BaseUrl` defaults to production. `new AnvilClient(apiKey)` reads `ANVIL_API_KEY` from the environment when the key is null.
  - OAuth access tokens are supported: `new AnvilClientOptions { AccessToken = ... }`. JWTs are sent as-is, other tokens base64 encoded, like node-anvil.
  - BREAKING: The API key is now sent as `Basic base64(apiKey + ":")`, with the trailing colon node-anvil and python-anvil send. It was sent without it.
  - Rate limits are learned from the first response that carries the `X-RateLimit-Limit` and `X-RateLimit-Interval-Ms` headers. Requests made before the first response arrives wait for it. The client counts requests over a sliding window, like the API, and only waits when the limit has been reached. Every client in the process with the same `BaseUrl` and credentials shares one limiter. A `429` is retried after its `Retry-After` plus 50ms, or after a second when there is no usable `Retry-After`, for as long as it takes; the `RateLimited` event reports each one, and `RateLimit` the current limit.
  - Every request is retried on `500`, `502`, `503` and `504`, and when it couldn't connect, up to `MaxRetries` times (5) with exponential backoff from 100ms. A request that was sent but got no response in time throws `TimeoutException` and is not retried, since the API may have processed it.
  - Requests time out after 5 minutes by default (`Timeout`, also per request through `RequestOptions`). They never did before. An `HttpClient` or `HttpMessageHandler` can be passed in, e.g. to use a proxy.
  - BREAKING: `AnvilClientException` is structured: `Errors` holds the normalized errors (GraphQL errors, REST errors and validation errors with their `Fields`), `StatusCode` the status (0 when there was no response), `Headers` the headers and `ResponseData` any partial GraphQL `data`. Its message is `"{status}: {name}: {message} (field: message, ...)"`. An error is any status outside 2xx, or a 2xx GraphQL response with `errors`; a non-JSON error, like a `502` from a proxy, keeps the start of its body. `HttpStatusCode` and `ResponseHeaders` remain as obsolete aliases, and `Data["Message1"]` is still filled. `BaseClient` is obsolete.
  - `RequestGraphQLAsync(query, variables)` returns the response's `data` (or deserializes it to a type), and `RequestRestAsync(method, path, json)`, `RequestRestBytesAsync`, `RequestRestStreamAsync` and `SendRestAsync` send any REST request, like node-anvil's `requestGraphQL` and `requestREST`. A full URL is accepted if it is on the client's `BaseUrl`, and refused otherwise. `AnvilClient.VERSION_LATEST` and `VERSION_LATEST_PUBLISHED` join `ClientConstants`.
  - The `User-Agent` is `dotnet-anvil/{version}`, configurable with `UserAgent`.
- `AnvilClient` has every method node-anvil has: `FillPdfAsync`, `GeneratePdfAsync` and `DownloadDocumentsAsync` return `byte[]`, with `*StreamAsync` and `*ToFileAsync` variants; `CreateEtchPacketAsync` and `GetEtchPacketAsync` return a typed `EtchPacket`, `ForgeSubmitAsync` a `Submission`, `GenerateEtchSignUrlAsync` the URL and `RemoveWeldDataAsync` whether the data was removed, plus `GetCurrentUserAsync`. Each takes its payload as a typed `Anvil.Payloads` object, an anonymous object, a dictionary, a `JObject` or a JSON string. `FillPdfAsync` sends `versionNumber` whenever one is given, including `0`.
- The GraphQL operations in `Anvil.GraphQL.Operations` match node-anvil's exactly, variable for variable, and are validated against the API schema in CI. `createEtchPacket` gains `organizationEid`, `enableEmails`, `createCastTemplatesFromUploads`, `duplicateCasts` and `allowUpdates`; `forgeSubmit` gains `enforcePayloadValidOnCreate` and `webhookURL`. `CreateEtchPacketAsync` and `ForgeSubmitAsync` take a `responseQuery` (the fields to return, with or without braces) and a whole `mutation`; `GetEtchPacketAsync` and `GetCurrentUserAsync` a `responseQuery`. BREAKING: the default response fields follow node-anvil: `documentGroup.id` and `weldData.id` are dropped (they are not in the API schema; use `eid`), `forgeSubmit` adds `status`, `continueURL` and `payloadValue`, and `createEtchPacket` adds `status`, `isTest`, `allowUpdates`, `numberRemainingSigners`, `webhookURL` and the timestamps. `ForgeSubmit.ErrorType` is removed, as the mutation has no such argument. The `Anvil.Queries` classes are obsolete and return the same documents.
- Add `AnvilClient.PrepareGraphQLFile` for multipart uploads of a path, bytes or a stream, anywhere in a mutation's variables under a `file` key: in a `DocumentUpload` passed to `CreateEtchPacketAsync`, or in the variables of any mutation sent with `RequestGraphQLAsync`, like `createCast`'s `$file: Upload!` ([#26](https://github.com/anvilco/dotnet-anvil/issues/26)). The request is sent per the GraphQL multipart request spec, and sent again after a `429` (a path is reopened and a seekable stream rewound). Base64 files in a `Base64Upload` are still sent inline as JSON. The variables are checked the way node-anvil checks them: a file may only sit under a `file` key, and a `file` must be a prepared file, a base64 object with `data`, `filename` and `mimetype`, or a `url` object.
- `Anvil.Payloads` has typed payloads built on the generated types, so every option the API documents is available: `FillPdfPayload`, `GeneratePdfPayload` (with `MarkdownContent`, `MarkdownTable`, `HtmlContent`, `Logo`), `CreateEtchPacketPayload` (`IsDraft = false`, `IsTest = true` by default), `ForgeSubmitPayload`, `EtchSigner` with all its options, `SignerField`, `SignatureField`, `Rect`, `Base64Upload`, and the files `EtchCastRef`, `DocumentUpload`, `DocumentMarkup` and `DocumentMarkdown`. An `in-person` signer is accepted, by the new `EtchSigner` and by the old `Anvil.Payloads.Request.Types.EtchSigner`, which no longer rejects any signer type ([#27](https://github.com/anvilco/dotnet-anvil/issues/27)).
- `RestClient` and `GraphQLClient` take an optional `baseUrl`, e.g. `new RestClient(apiKey, baseUrl)`. It defaults to production, `https://app.useanvil.com`, and every URL derives from it: REST requests go to `{baseUrl}/api/v1/`, GraphQL to `{baseUrl}/graphql` (no longer `https://graphql.useanvil.com`) and document downloads to `{baseUrl}/api/document-group/`.
- Add `test-client/`, a console app that runs every client method against a real environment: `ANVIL_API_KEY=... dotnet run --project test-client`.
- Add `schema/`, the Anvil GraphQL schema (from the published `@anvilco/types` package) and OpenAPI spec, and `dev/check-graphql.mjs`, which validates the client's queries and mutations against the schema.
- Add `Anvil.Types`: C# types generated from the API's OpenAPI spec and GraphQL schema, the .NET counterpart of `@anvilco/types` and `python_anvil.types`. `Anvil.Types.Rest` has the REST request bodies, `Anvil.Types.GraphQL` every type in the schema, and `Anvil.Types.Operations` the arguments of every query and mutation, like `CreateEtchPacketArgs`. Generated by `npm run generate` in `dev/`; CI fails when they are out of date with `schema/`.
- A Sync API Types workflow refreshes `schema/` and regenerates `Anvil.Types` after each production deploy, opening a PR when anything changed.
- The unit tests run the client against a real HTTP server on a loopback port as well as a scripted handler, so the auth encoding, multipart bodies, rate limit timing, retries and error handling are checked on the wire. CI fails when line coverage of the hand-written code drops below the threshold in `ci.yml`.
- Line endings are LF, and `.gitattributes` keeps them that way.
- Update the test dependencies (xunit 2.9, Microsoft.NET.Test.Sdk 18, coverlet 10) and Newtonsoft.Json to 13.0.4. Moq was unused and is removed.
- Sync the generated API types in `Anvil.Types` with the production API.
